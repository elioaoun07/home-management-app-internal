# Agentic OS — PM.2 product design

[Agentic OS index](<_index.md>) · [Skill launchpad](<08 - Skill Launchpad.md>) · next: [Visual, motion and game layer](<10 - Visual, Motion and Game Layer.md>) · item: [R97](<../../PM Tooling/PM Tooling — Master Book.md#r97>)

## Two products, one server

| | PM.1 — Library | PM.2 — Cockpit |
|---|---|---|
| Is for | Reading and editing what is written | Seeing what is happening and starting things |
| Holds | Documents, checklists, Master Books, decisions, inbox, shipped history, plans, Fable 2 | Today, launches, sessions, setup, rules, scores |
| Source | Markdown files | The registry, the flight recorder, git, the same checklists (read-only) |
| Changes files | Yes: tick, move, capture, rename | Only through an explicit action that PM.1 could also do (Ship, capture) |
| Feel | Calm, text-first | Live, visual, animated |

Both are served by `pnpm pm`. PM.2 is the default screen once it is ready; PM.1 is one click away as **Library**. Until then PM.2 lives at its own path and PM.1 is unchanged.

## Where today's screens go

So that there is never a second home screen or a second analytics page:

| Today | Goes to | Note |
|---|---|---|
| Home | PM.2 **Bridge** | The counts become one row; the Today block from [R86](<../../PM Tooling/PM Tooling — Master Book.md#r86>) is the main content |
| Delivery (launch, run, review, UAT) | PM.2 **Launch** and **Sessions** | A delivery run is a session with an item attached |
| Analytics | PM.2 **Score** | Backlog charts stay; session and tier panels are added |
| Sprints | PM.2 **Plan**, secondary navigation | Unchanged apart from [R87](<../../PM Tooling/PM Tooling — Master Book.md#r87>) |
| Work, spaces, board and list | PM.1 Library | The item list is a view over checklist files |
| Reader, Documents, Inbox, Decisions, Activity | PM.1 Library | Already document views |
| Classic UI and the second-generation UI | Retired | Existing R6 |

## Navigation

Primary, five slots, same bar on desktop and phone: **Bridge · Launch · Sessions · Setup · Score**. Secondary: Plan, Conflicts, Library.

## Screens

### Bridge

One question: what now?

```text
┌ Needs you (3) ──────────┐ ┌ Running (1) ───────────┐ ┌ Next up ───────────────┐
│ UAT  BUD-95  ready      │ │ HUB-118 · build · 6 min │ │ BUD-89   Deliver ▸     │
│ Q    DLV-150 1 question │ │ ▓▓▓▓▓░░ checks next     │ │ BUD-90   Deliver ▸     │
│ DEC  DEC-07  blocks R45 │ └─────────────────────────┘ │ HUB-119  Deliver ▸     │
└─────────────────────────┘                             └────────────────────────┘
 Setup  ◐ 7/29 guarded · 4 conflicts      Streak  ✦ 3 clean      Now 5 · Next 96 · Later 143
```

Primary action: Deliver on a Next-up row. Everything else on the page is a number that opens its own screen.

### Launch

The [skill launchpad](<08 - Skill Launchpad.md>): skill cards, recipes, a form, a rendered prompt, tier and location, one Launch button. Starting from an item pre-fills the `item` field and suggests the skill by the item's kind (bug → `fix-bug`, ERA report → `era-wire`).

### Sessions

A list, newest first: agent, tier, item, duration, verdict strip (green, red, grey ticks for the 29 rules), outcome. Opening one shows the [flight report](<06 - Flight Recorder.md>) as a horizontal timeline:

```text
prompt ─ skills ─ reading ─ edits ─────────── hooks ─ checks ─ verdicts ─ UAT ─ ship
  ●        ●●        ●●●     ●●●●●●●●●●        ✓✓✗✓     ✓✓✓      27✓ 1✗    ◌      ◌
```

Clicking a red mark opens the file and line. A session with an item shows the item's other sessions beside it, which is the delivery view. Two sessions can be pinned for comparison with their setup diff between them.

### Setup

Three tabs.

**Map.** Columns left to right: Agents · Instructions · Skills · Hooks and permissions · Checks and detectors · Rules. Lines connect what enforces or mirrors what. Selecting an agent greys everything it does not have, which makes the gap between Claude and Codex the first thing seen. Selecting a rule lights its whole chain or shows that it has none.

**Rulebook.** The 29 rules as cards: number, short title, shield level, baseline count with a trend line, last session that failed it. Sort by "weakest first".

**Conflicts.** The rows from `os:check`, grouped by class, each with the two sources side by side and "Open as item".

A small **fingerprint glyph**, generated from the setup hash, sits in the header. When the setup changes the glyph changes, so a glance tells whether two sessions ran under the same rules.

### Score

Panels: clean rate over time; rule failures by rule; process completeness; tokens per shipped item by tier; added against shipped per week; escapes. Tier cards summarise each alias with its real numbers and sample size. The Arena, when it exists, is a tab here.

### Plan

Today's Sprints view with elapsed weeks closed.

## Empty and early states

PM.2 is useful before any session is recorded: Setup works from the registry alone on day one. Sessions and Score show what they need ("no sessions recorded yet · wire the recorder") and never fake a chart. The first ten sessions show as rows, not rates.

## Phone

Bridge, Sessions (read-only) and UAT work on the phone. Launch and Setup are desktop screens first: a form with pickers and a six-column map do not fit 390 px, and starting agents from the phone is out of scope ([vision](<01 - Vision and Hype Filter.md>)).

## Rules the design holds itself to

- Hard Rule 28: labels, numbers and one- or two-word buttons. Help sits behind an `i`.
- Every number opens its evidence in at most one click.
- No screen exists in both products.
- No state lives only in PM.2. Clearing `.os/` loses history, never backlog or rules.
- Colour carries state consistently: the same green, amber and red as verdicts everywhere; person colours stay person-absolute where a person appears (Hard Rule 14).
