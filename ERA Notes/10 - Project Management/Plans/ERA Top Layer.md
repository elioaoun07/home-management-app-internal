# ERA Top Layer

This is the accepted cross-campaign specification. The [campaign checklists](<../_index.md>) own pending work, priority and completion. The original [September 2 specification](<../_Archive/Plans/ERA Top Layer — Master Plan (2026-09-02).md>) preserves the detailed packet fields, source allowlists, fixtures, metrics and initial analysis; its superseded claims are reconciled here and in the owning books. No independent execution checkboxes remain in this plan.

## Outcome and ownership

ERA is the assistant for household questions, confirmed actions and proactive messages. Hub Chat is the household conversation and message-action bridge. Budget analysis reports become a Budget-face capability before the floating assistant is retired. One router, registry and assistant persistence; preserve the existing precision tools.

The program progresses from trustworthy facts and owner evidence, through deterministic briefing and reactive capture, to proposals/learning and native delivery. L2/L3/L4 remain program labels, not evidence that a capability is useful. A cron return, persisted notification, device delivery, human attention and accepted useful action are different observations.

## Gate targets and scoring

The original windows remain a baseline for comparison, not newly promised dates: G0 September 14, G1 October 12, G2 November 9, G3 December 7, G4 December 31, 2026. Record observed pass/miss with evidence in the owning book and link the gate here. A missed target is not evidence a task was done.

- **G0:** CI, current owner-applied schema evidence, cadence-aware cron liveness, honest offline refusal, scoped security/access evidence and verified import repair.
- **G1:** five consecutive eligible delivered briefings (not merely cron rows), exactly-once retry, real `/era` door, canonical signal fixtures, scoped reactive reads/writes, durable replay, Trips contract proof, usage truth and native accounts.
- **G2:** treaty, shared voice preserves time, one top-view request, partner consent/hour/color acceptance, fallback behavior, export/restore and scoped security review.
- **G3:** shared policy caps/quiet behavior, confirmed cards, unique anomaly proposal, qualified module signals, calm accessible bell.
- **G4:** both store-track builds, native delivery at the eligible local hour, and unregressed web push.

No gate is newly scored by this documentation session. Count executed/eligible evidence, never document count or an SDK acknowledgment. Original raw SQL and test examples remain historical procedures to revalidate before use, not instructions for agents to call production.

Approximately 37 sessions were originally planned against 34 slots. Retain the explicit sacrifice order on a missed gate: E-18 picker; M-08 Outfits; M-07 medications; E-23 ranker; N-05 native wave 1. Two consecutive missed gates trigger a native Phase-4 slide and re-scope; record that decision, never stretch dates silently. The original prose ordered the native slide differently in two places; an actual reschedule requires the owner's recorded choice, not a refactor-made calendar.
