# PM Command Center (`pnpm pm`, Delivery, `/pm`, `/pm/live`)

**Type:** Cross-cutting (tooling — not an app module)
**Routes:** local `pnpm pm` (React primary, `?ui=classic` Preact reference, `?ui=old` legacy rollback) · hosted read-only `/pm` · phone relay `/pm/live`
**Owners:** [PM Tooling](../../../10%20-%20Project%20Management/PM%20Tooling/PM%20Tooling%20—%20Master%20Book.md) (surfaces, parsing, identity) · [Delivery](../../../10%20-%20Project%20Management/Delivery/Delivery%20—%20Master%20Book.md) (execution) · accepted spec [Plans/Command Center](../../../10%20-%20Project%20Management/Plans/Command%20Center.md)

## What it does

Reads the eleven campaign checklists and Master Books under `ERA Notes/10 - Project Management/` as the only backlog, lets the owner organize and complete outcomes, and runs Delivery sessions (V1 operating, V2 prepared for the first owner-started desktop trial). Markdown is the task store; `.delivery/` and `.pm/` hold runtime state.

**Local Delivery setup (2026-09-13):** V2 is ready for the owner-started DLV-107 desktop trial. `scripts/delivery-v2/setup-subscriptions.mjs` provisions native subscription credentials and a dedicated provider proxy; `worker/subscription.mjs` rejects paid/unknown auth and unavailable included usage before SDK jobs; `worker/egress.mjs` enforces exact-host tunnels and kernel UID routing; `worker/seccomp.mjs` adds scoped nested-sandbox support to Moby's default policy. `worker-boundary.mjs` owns isolated volumes, stdin dispatch and auth readiness; `probes/worker-qualification.mjs --boundary <file> --backend <id>` qualifies exact image/profile/proxy bindings. `trial-checks.mjs` renders DLV-107's real missing-item link against synthetic receipts. Active policy and credential artifacts stay local under `.delivery/` and Docker named volumes. See Delivery DLV-96/97/110/111 and the local test wizard for current evidence and expiry/remote limits.

## Gotchas

- Compare IDs normalized (`SCH-4.3b` ≡ `SCH-4.3B`); display the source spelling (`Work.label`). References never truncate to a different ID.
- Anchors are GitHub slugs (one hyphen per space, none collapsed) — the same function `pnpm pm:check-docs` validates links with.
- Checkbox writes require `expectLine` (428 without); a changed row, mismatched `expectId` or duplicate ID in the file is 409. Never resolve a write by ordinal alone.
- V2 `deliver` requires a selection witness and binds the Master Book `### <ID>` revision into the contract. The run names its executor, model and effort; there is no installation default (`POST /api/delivery/v2/executor` is 410).
- V2 dispatch needs a container `runtime` in `.delivery/v2/execution-policy.json` and a qualification receipt bound to that image/SDK/boundary; without both, launch refuses. Every provider call is preceded by an exclusive claim and a recheck of source, acceptance, grant, policy revision, qualification and resources.
- V2 commands authenticate by paired session + `x-era-csrf`; the body's `actor` is ignored. Unknown usage stays unknown (never $0); a failed PM writeback retries only the writeback.
- V2 launch recommendations are deterministic local policy and persist with any owner override in `runs.settings_json`; the production launch UI does not print their rationale. Focused is bounded to one plan and implementation job with no automatic repair; use Investigate for further discovery.
- Prepared Focused plans may omit the planning job only with explicit complete owner-reviewed low-risk material and existing runnable checks. They still require owner approval, one implementation, protected verification and Apply. New `binding-v2:` contracts separate explicitly delimited advisory guidance; legacy fingerprints remain whole-section. Worker images must advertise `task_brief_version: 1`; old images refuse qualification binding rather than lose the recovery input.
- `worker/runner.mjs` runs only inside the worker image; `ERA_V2_SYNTHETIC=1` restricts it to scripted writes. The real-container smoke is opt-in: `ERA_V2_DOCKER=1 pnpm exec vitest run tests/delivery-v2/worker-boundary.docker.test.ts`.
- `_Archive/` is never scanned. Only `_Archive/Cancelled Log.md` is read, as history (`world.sources`), never as backlog.
- No surface writes production data (Hard Rule 26); relay schema changes are owner-run migrations (`migrations/2026-09-12_pm-v2-relay.sql`).
- Relay rows are `cc:<installation>:<kind>[:<key>]`; a phone command's id is its relay row id and its V2 `command_id`, so a retry is the same command end to end. A timeout or a stale heartbeat is never shown as failed or stopped.
- Apply never runs candidate code on the host: integrated checks go through `runtime.checkExecutor` only; with no checker the application is `checks-pending`, not `applied`. The integrator refuses protected paths (`PROTECTED_PATHS` + policy `apply.protectedPaths`), links/junctions, case collisions and any path changed since the base.
- Parallel items (Phase 5): at most two writers (`concurrency.maxWriters`; the ceiling is `WRITER_CEILING` in code). Every job that may still be running — reserved, active, paused, unknown, or asked to stop without an observed stop — holds a job slot. Writer slots are derived from job and run state, not a stored lock. A missing `**Touches:**` line is unknown scope and blocks writing beside another reservation. A verified, unapplied candidate reserves its paths until applied, rolled back, superseded or released (control `release`). The queue rides the relay `v2runs` row; pre-launch `assess` is local only. V1's `isBuildLockActive` guard is unchanged.
- `/pm/live` mounts the shared views; `?ui=legacy` is the rollback. The PM app CSS loads only with the lazily imported `CommandCenterLive` chunk (root `font-size: 14px`) so the legacy Tailwind view is unaffected.
- Dashboard units never mix: a history record is a receipt, a work outcome is one exact ID (latest dated receipt; an ID open again is Reopened), a delivery attempt is a session/run. V1 SHIPPED is "Accepted" with disposition unrecorded; V2 verified candidate and applied change are reached levels, not slices. Only records with a stated day (or a range inside one week) are placed in a week. Estimated USD, tokens and settled amounts are summed separately with known/total.

## Recovery integration (2026-10-17)

- **Incomplete native packages after a zero installer exit:** `checker-package-diagnostic.mjs` traces exact lockfile/SRI leaf payloads. `stage-checker-environment.mjs` keeps pnpm's store in a new owned disk volume, retains failures, and confirms cleanup before publishing a receipt. `worker/native-runtime-probe.mjs` requires offline native execution for declared Codex/Claude SDKs.
