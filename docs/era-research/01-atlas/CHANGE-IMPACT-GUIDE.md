# ERA Change Impact Guide

[README](README.md) · [Capability Map](CAPABILITY-MAP.md) · [Architecture](ARCHITECTURE.md) · [Critical Flows](CRITICAL-FLOWS.md) · **Change Impact**

Before you change something shared, find it here. Each entry says who depends on it, how a mistake would show up (usually it would not show up at all), what to check, and which steps only the owner can take. It complements the repo's playbooks in `.claude/skills/`; it does not replace them.

## 1. How to use this guide

1. Find the component you will touch in [§2](#2-blast-radius-by-shared-component). If it is not listed, `grep` its export across `src/` and treat more than about five consumers as shared.
2. Read the **silent failure** column. ERA's dangerous bugs do not crash; they leave a wrong balance, a duplicate occurrence, a partner seeing too much, or stale numbers on screen (Design Doctrine §3).
3. Run the listed checks. They are existing tests or commands; nothing here asks for new tooling.
4. If the change needs a DB change, the owner runs the SQL. Write `migrations/YYYY-MM-DD_*.sql` first, then update `migrations/schema.sql` (Hard Rule 24); no agent touches production (Hard Rule 26).
5. Write the acceptance example from [§4](#4-acceptance-example-template) before you merge.

Consumer counts are files, not call sites.

## 3. Common changes and what they touch

### Add a column to `items`

Migration + `schema.sql`; `createItemSchema` and `prepareItemCreate()` in `createContract.ts`; the `create_item_complete` and `create_items_bulk` RPC bodies; `get_schedule_bundle` if read on the hot path (Hard Rule 21); `health_rebuild_medication_reminders` and the fitness activation if the column has a non-null default or meaning; `src/types/items.ts`; the browser-direct update hooks; the Activity Log trigger only reads `title`/`name`/`label`/`description`/`content`, so a new title-like column is not picked up automatically.

### Change how a completion is recorded

Every writer of `item_occurrence_actions` (`completeItems.ts`, `/api/items/[id]/actions`, `useUncompleteItem`, `useUndoOccurrenceAction`, `health_set_dose`, fitness functions, trip cascade) and every reader (`expandOccurrencesInRange`, chores week builder, item-reminders cron, both mirror triggers). Worked example from J4 in [CRITICAL-FLOWS](CRITICAL-FLOWS.md#j4--start-a-medication-course-and-tick-a-dose).

### Add or change a money route

`money-rules` skill; `getAccessibleAccount(...).canWrite` and the account's real type, never a default `"expense"` (M3); claim first, then move money, 409 on a lost claim (M2); a client id for anything that can be retried (O2, Audit #1); `safeFetch` with an explicit `timeoutMs`; a route test with a worked balance example; invalidate `account-balance`, `accounts`, `transactions`, `dashboard-stats` (the `FEATURE_QUERY_KEYS.transaction` list is the minimum).

### Give ERA a new action

`/era-wire` for an already-shipped manual feature. Registry entry with source routes; resolver through `routeWrite`; one artifact; one Gym case; one row in `artifacts.contract.test.ts`; Reach Matrix regeneration (`ERA_REACH_WRITE=1 pnpm vitest run src/features/era/reach.test.ts`). Writes that move money or recurrence go to a high-effort session (`era-wire` STOP conditions).

### Add a page or module

`new-module` skill: feature folder, API route, page, Feature Map row, vault doc, `CLAUDE.md` Feature Index, Atlas entry (Hard Rule 23), `ConditionalHeader`/`MobileNav` if isolated, a manifest only if installable, and an Activity Log registry decision for its tables.

### Change date or time logic

`timezone-handling` skill. Local `YYYY-MM-DD` from `formatDate()`; never `toISOString().split("T")[0]` for a user date (53 call sites remain in `src/`); anchor bare dates at noon for display; DTSTART through `buildFullRRuleString()`; billing month through `startOfCustomMonth()`.

### Change service-worker caching

Decide per prefix whether stale data is acceptable (money is not; see P2 in [ARCHITECTURE §9](ARCHITECTURE.md#9-proposed-designs)); bump the cache name; test a cold offline start and a warm online refetch on a phone.

### Re-enable the trip cascade (TRIP-39)

Refresh `db-state.json` first, then review the three snapshot behaviours in [ARCHITECTURE F-U6](ARCHITECTURE.md#f-u6-the-trip-cascade-that-would-return-is-only-visible-in-a-stale-snapshot); flip `TRIP_CASCADE_ENABLED`; verify `EXECUTE` grants (TRIP-39 acceptance); trips activated while disabled have no ledger rows, so completing them reverses nothing.

## 4. Acceptance example template

Write one per shared-component change, with fictional data, before merging:

```text
Component:        <file / symbol>
Change:           <one sentence>
Consumers hit:    <list from §2>
Before:           <fictional state, e.g. Wallet $240.00; "Dentist" Thu 12 Nov 16:00 with alert 15:30>
Action:           <what the person does, online / offline / slow>
Expected after:   <exact rows and screens on BOTH phones>
Duplicate test:   <same action twice, or replayed after a timeout → still one effect>
Interruption:     <close the app after the request is sent → state after reopening>
Undo:             <exact inverse and its result>
Owner steps:      <migrations to run, flags to flip, device to test>
```

Example, filled in for P1 in ARCHITECTURE: _Component_ `useDeleteItem`; _Before_ "Dentist" Thu 12 Nov 2026 16:00, alert 15:30, Google event present; _Action_ delete from the Event dialog online; _Expected_ item in Recycle Bin, alert inactive, event gone, partner's Schedule no longer shows it; _Duplicate test_ delete queued offline and replayed twice → one Recycle Bin row; _Undo_ restore → alert active again only if 15:30 is still ahead; _Owner steps_ none for P1 itself.
